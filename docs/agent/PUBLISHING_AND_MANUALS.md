# Publishing and Field Manuals

## Published Manual editing home

Published Field Manuals live in:

`content/field-manuals/`

in the public LUV repository on `main`.

The website build generates public manual pages and related outputs from these source files.

## Before writing a new Manual

Read:

1. private brain `production/FIELD_MANUAL_RULES.md`;
2. relevant private canon/theology source;
3. recent published manuals for continuity;
4. any current owner instruction for the release.

Do not assume an old manual-production template is still binding if the current private production rules supersede it.

## Public language

Spanish by default.

## Content purpose

Field Manuals should serve awakening, formation, responsibility, vigilance, discipline, truth, Christian faith, and practical action.

Avoid generic influencer motivation or disconnected self-help copy.

## Published-file integrity

A published manual is a public historical artifact.

Do not silently rewrite it because:

- the private story canon advanced;
- a newer visual standard exists;
- a new social campaign uses different wording.

Revise a published manual only when the request actually concerns that manual.

## Generated website output

The public build may regenerate:

- manual index;
- individual manual HTML;
- sitemap;
- RSS.

Edit the documented source file rather than bypassing the build system.

## Derivative content

A Manual may produce:

- social posts;
- quotes;
- briefings;
- carousels;
- podcast material;
- email/newsletter material;
- discussion prompts;
- infographics.

Not every derivative must be created for every manual.

Use the current private channel/content production rules and Eric's requested release scope.

## Independent creative work

Standalone character art, quotes, scenes, or social concepts may also exist independently of a Field Manual when current private production governance permits it.

Do not force every social post to pretend it came from a Manual.

## Publication authority

Drafting is not publication.

Creating a source file is not necessarily approval to deploy or post.

Follow the current task and the target system's own approval/publishing rules.
